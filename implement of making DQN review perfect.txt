## Phase 4: Pre-declared sensitivity sweep (~2 days) -- main scientific task

Question: is the DQN-vs-Max-Weight tie caused by the easy placeholder environment?

4.1 Freeze the grid in docs/EVAL_PROTOCOL.md BEFORE running. Proposed axes:

| Axis | Values |
|------|--------|
| Logistic r50 | -90, -82, -75 dBm |
| Logistic slope | 2, 4, 8 dB |
| Node distances | current set; a set spreading nodes across the steep part of the curve |
| Burst loss | current; 2x worse |
| Arrival probability | 1.0, 0.5, 0.2 |

Full factorial = 3x3x2x2x3 = 108 cells. If too heavy, freeze a fractional subset with the selection rule written down.

4.2 Build harness: extend eval/run.py and tools/run_eval_sweep.py to accept a scenario spec (parameter overrides);
write scenario ID into output path and run_meta.json; run DQN + all baselines per cell.
Decide BEFORE running: evaluate existing DQN in shifted envs (generalisation) vs retrain per regime (capability).
Suggested: both, for 3-4 headline cells, clearly labelled.

4.3 Analysis (eval/stats.py, eval/figures.py):
- Paired differences DQN-MaxWeight and DQN-CAG per cell, CIs across eval seeds AND training seeds.
- Pre-declared equivalence margin so "tie" has a definition (not "p > 0.05").
- Multiple-comparison correction across cells.
- Heatmap of gain per cell.

Done when: all cells run, every result reported, and a one-paragraph statement of where DQN helps / ties / loses.

## Decisions needed

1. Are the original 5 checkpoints recoverable from the training laptop? If not, Phase 3 becomes required.
2. Sweep breadth: full 108-cell grid, or a smaller frozen subset?
3. Phase 4 approach: evaluate existing DQN across environments, retrain per regime for headline cells, or both?
4. Reward normalisation / gamma: may the training config change (needs a documented protocol amendment), or is it locked?

## Risks

- DQN may still tie Max-Weight everywhere. The plan reports this honestly (consistent with decision D6.2: report negative results).
- Retraining changes the model the current headline numbers describe; keep old results labelled as such.
- The pytest suite and RL code paths on this branch were not verified (SB3/torch not installed during the audit).
  Check this first in Phase 1 before anything else changes.
